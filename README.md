# Vaska de Gamma

Исходники оформления и обновление отдельного тестового сайта.

Ветка `site-vaska-de-gamma` в `ln71v/kombain` используется только для сайта.
Ветка `main`, установщик Комбайна и сторонние проекты не изменяются.
`site/` содержит публичные статические файлы, `manifest.json` — их SHA-256.
Нет аналитики, внешних шрифтов, контактов или ссылок на личные профили.
Изображения демонстрационные. Контакты пока не подключены.

## Как вносить изменения

1. Изменять файлы только в этой ветке, в `site/`.
2. При изменении ресурса в `site/assets/` добавлять первые 12 знаков SHA-256 к имени.
3. Обновлять `manifest.json` со списком публикуемых файлов и SHA-256 их содержимого.
4. Коммитить файлы и манифест одним коммитом. Не использовать force push.

Сайт не читает информацию о репозитории из HTML. Новый домен не требует смены
оформления или ветки; DNS/TLS настраиваются отдельно.

## Однократная настройка на стенде

`deploy/bootstrap.sh` запускается от root с SHA проверенного коммита этой ветки.
Он проверяет каталог в действующем Caddyfile и наличие работающей службы сайта,
сохраняет резервную копию, устанавливает фиксированный Python-обновлятор и свой
таймер `vaska-site-sync.timer` (раз в две минуты).

Обновлятор меняет только статические файлы в `/usr/local/share/kombain-site/www`.
Он не выполняет скачанные скрипты, не обновляет сам себя и не скачивает конфиги
сервера. Все загрузки проверяются по SHA-256 до изменения работающего сайта.
При недоступности GitHub или неверном манифесте остаётся прежняя страница.
Резервные копии — `/var/lib/vaska-site-sync/backups/`, доступны только root.
Предыдущие файлы assets сохраняются; их очистка и очистка бэкапов выполняется отдельно.

Существующие службы сайта/VPN, их порты, сертификаты и Nginx/Caddyfile не меняются.
Старый сертификат и его продление требуют отдельного решения владельца сервера;
настройка обновления HTML не решает вопросы TLS или DNS.

Проверка: `systemctl status vaska-site-sync.timer --no-pager`
и `journalctl -u vaska-site-sync.service -n 20 --no-pager`.
Остановка автообновления: `systemctl disable --now vaska-site-sync.timer`.
Откат: остановить таймер и восстановить нужные файлы из резервной копии;
при необходимости также вернуть предыдущий коммит сайта без force push.
