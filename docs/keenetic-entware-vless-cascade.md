# Keenetic Ultra — переустановка Entware и подключение каскада RU → Финляндия

25 ноября 2026 года, Keenetic Ultra KN-1811, KeeneticOS 5.1.10.

## 1. Бэкап и подготовка USB

- Через «Настройки системы → Системные файлы» скачали `startup-config` и образ прошивки. В Entware отдельно сделали архив `entware-etc.tar.gz` из `/opt/etc`, проверили чтение списка архива и скачали его с роутера через MobaXterm.
- Целевой носитель — Samsung Flash Drive FIT, раздел `Flesh`, около 58,5 ГБ. Для форматирования через «Накопители и устройства» нужны компоненты файловой системы ext и её утилит. Когда в диалоге предлагался только SWAP, форматирование отложили и проверили компоненты. После форматирования в EXT4 флешку переподключили, и Keenetic снова её увидел.
- Бэкап сохранили для отката. Рабочая конфигурация Xray создана с нуля.

## 2. Чистая установка Entware

- Для KN-1811 использовали `EN_aarch64-installer.tar.gz` из каталога Entware AArch64. Запакованный архив положили в `install/` в корне USB-раздела, выбрали раздел в настройках OPKG и сохранили.
- Журнал показал монтирование в `/opt`, установку базовых пакетов, генерацию ключей SSH и запуск Dropbear. Последняя запись установщика в присланном журнале относилась к шагу 4 из 5. Работу Entware подтвердили напрямую — SSH на порту 222, `/opt/bin/opkg --version` и обновление обоих репозиториев командой `/opt/bin/opkg update`.
- Установили `xray curl jq` через OPKG. Версия Xray — 26.10.29. Пакет поставил шаблон `/opt/etc/xray/config.json.example` и службу `/opt/etc/init.d/S24xray`.

## 3. Отдельный клиент на RU

- Перед добавлением устройства проверили, что в локальном генераторе `/opt/kombain/src/modules/vless.sh` обработка `finland` идёт после `aup_apply` и до проверки Xray. Сохранили копии `clients.json` и `config.json` из `/opt/kombain/vless/`.
- На установленной версии вызов с аргументами открыл интерактивное меню. Клиента `keenetic` добавили через «VLESS Reality → Добавить устройство».
- После пересборки `systemctl is-active kombain-xray` вернул `active`. В конфиге запущенной службы проверили наличие клиента `keenetic`, выхода `finland` и последнего правила с этим выходом. Проверка вернула `true`.

## 4. Проверка и запуск Xray на Keenetic

- Профиль клиента ввели в SSH с отключённым отображением ввода. Из него собрали временный конфиг Xray с VLESS REALITY на RU и локальным SOCKS5 на `127.0.0.1:1086`. Тест через `curl --socks5-hostname 127.0.0.1:1086` к `https://api.ipify.org` вернул `45.148.127.22`, адрес финского выхода. Временный процесс остановили.
- При создании постоянной конфигурации Xray отклонил временный файл без расширения даже с параметром `-format json`. Сработало размещение файла `config.json` во временной папке. После `xray run -test` конфиг установили в `/opt/etc/xray/config.json` и запустили `/opt/etc/init.d/S24xray start`.
- После старта первый запрос пришёлся на момент, когда порт ещё не слушал. Повторный запрос через постоянный SOCKS вернул `45.148.127.22`. Команда установки предусматривала остановку службы и удаление созданного конфига при неуспешной проверке.

## 5. Подключение в KeeneticOS

- «Интернет → Другие подключения → Прокси-подключения». Имя — «Каскад RU-FI», тип — SOCKS v5, адрес — `127.0.0.1:1086`, аутентификация отключена. Для создания отдельного интерфейса галочку «Использовать для выхода в интернет» оставили снятой по инструкции.
- Пользователь подтвердил работу подключения. Состав маршрутов по доменам и устройствам в ходе этой проверки не фиксировали. Для нейросервисов используется ранее настроенная схема AdGuard Home по DNS, которую пользователь подтвердил на компьютере.

Серверная часть описана в [памятке о каскаде Россия–Финляндия](vless-cascade-russia-finland.md).

## REALITY — диагностика TLS-отпечатка

Для новых каскадов начинайте с `fingerprint: "chrome"` в исходящем REALITY. В профиле VLESS этому соответствует `fp=chrome`. На маршруте RU → Нидерланды с Xray 26.2.6 на RU и 26.11.9 на NL профиль с `firefox` получил `REALITY: received real certificate`, хотя обычный TLS через nginx проходил. Смена отпечатка на `chrome` при тех же ключах и SNI дала выход `78.17.135.82`. На Keenetic проверен тот же выход через SOCKS5 `127.0.0.1:1087`, клиент `ru-nl`. Для других серверов это первая проверка при аналогичном сбое. Причину их прежних сбоев отдельно не подтверждали.
